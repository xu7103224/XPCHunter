# 交接：实机验收打通 + 两个根因已定位修复（2026-10-19）

## 本轮里程碑

**1) 打通了实机验收**（此前一直卡住的环境问题）

- `vmrun` 必须在**关闭沙箱**下调用（`dangerouslyDisableSandbox`），否则静默失败；
- VM 常停在**锁屏**（`LogonUI.exe` 在、`explorer.exe` 不在）→ SSH/VMwareTools/
  `con_run` 全部不可用；须先用 **VNC 控制台**解锁：
  `python build/audit/vnc_input.py 127.0.0.1 5910 key space / key enter / type 123 / key enter`
- 驱动加载需**管理员**（`xuq` 的令牌被 UAC 过滤，`sc` 会报"拒绝访问"）。
  提升方式：VNC 发 **Win+X → A**（管理员终端）→ 截图确认变暗（mean<120）→
  **点击 UAC 的"是"按钮（坐标约 660,558）** → 在打开的终端里 `type` 脚本路径。
- kd 停住时 guest 冻结，`vmrun` 全部超时 → **先 `kd_go`**。

**2) 抓到并修复了实机 0x50 蓝屏的根因**（`47e0697`）

驱动能加载但立即蓝屏：`rtZ19+0x3bbdd  movzx eax,word ptr [rax+6]  rax=0`。
根因：`FindKernelInitSection` 读的 `SectionName` 是**声明后从不赋值**的局部（初值 0），
MSVC 把 `*(WORD*)(SectionName+6)` 折叠成绝对地址 `[6]`。
同族共 **7 个函数**（FindKernelInitSection、FindKernelDataSectionForImageNotify2/3、
ForDeviceIoControl/2、ByCode、ByData）—— 全部逐条对照原始重写。

**3) 找到"扫描不命中"的解码器根因**（`a947ddc`，一次补 8 个槽）

`DecodeModrmAddressingMode`（sub_14008C18C）三处错：
1. Flag 支读 `[rcx+4]`（原始 0x14008C19C），旧代码读 Context+0x01 → 读到垃圾 →
   RegIndex 停在 4（置 0x20）而非 11（置 0x40）→ 描述符 **+0x50 = 0x21 而原始 0x41**；
2. AddressMode 读 `[rcx+8]`（0x14008C1B6），旧代码读 Context+2；
3. AddressMode==1/2 的 RegIndex 映射写反（原始 1→4、2→11）。

**定位手段**：新增 `build/audit/oracle_type_seq.py` —— 从指定文件偏移起，
逐轮比对原始与我方 `ReadPESectionEntry` 产出的**节区类型序列**，
一眼看出"唯一差异是 +0x50 的 0x41 vs 0x21"。
