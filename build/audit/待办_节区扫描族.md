# 待办：节区扫描族（SsdtHook.c / Minifilter.c）的同族缺陷

> 2026-10-17 用脚本扫出。**同一根因在 50 处函数中重复**，是本轮 GT 对齐度
> （orig 1315 vs 我方 1257）剩余缺失槽的主要来源。

## 缺陷模式（三类，同源）

在 `SsdtHook.c` 的 Hook 族与 `Minifilter.c` 的扫描族里，普遍存在：

```c
unsigned int EntryFlags = 0;      // ← 声明后**永不被赋值**
__int64      FieldValue = 0;      // ← 同上
unsigned int FieldFlags = 0;
__int64      FieldValue2 = 0;
unsigned int SectionSize = 0;
...
for (...) {
    /* 旧代码：读指针在**读取之前**推进（原始是读完再 += Entry[0xF0]） */
    *(ULONG64 *)((PUCHAR)&ReadContext + 0x08) += *(unsigned int *)((PUCHAR)SectionEntry + 0xF0);
    result = ReadPESectionEntry(&ReadContext, SectionEntry);
    ...
    if (SubType == X && (FieldValue & M) && !EntryFlags && (FieldValue2 & M2)) { ... }  // ← 恒假
}
```

三处错误：
1. **字段未绑定**：上述局部应等价于 `SectionEntry` 的固定偏移（见下表），
   它们恒 0 → 所有依赖它们的条件永不成立 → 结果 GT 槽永不写入。
2. **读指针推进顺序**：应为「读完本条 → `ReadPtr += Entry[0xF0]`」。写在读取之前会让
   首轮推进上一轮的 0、之后整体错位一轮。
3. **目标公式**：原始是 `v = Entry[0x78] - ImageBase + ctx.ReadPtr`（用 ctx 读指针），
   旧代码常用 `MatchSize + FieldFlags - ImageBase`（MatchSize 的语义不等价）。

## 字段 ↔ 描述符偏移 ↔ 宏

| 变量名 | 描述符偏移 | 头文件宏 | 类型 |
| --- | --- | --- | --- |
| `SectionSize` | +0xF0 | `PE_DESC_SECTION_SIZE` | unsigned int |
| `EntryFlags` | +0x58 | `PE_DESC_ENTRY_SIZE`(0x38 是另一字段，注意核对) | int |
| `FieldValue` | +0x50 | `PE_DESC_FIELD_VALUE` | __int64 |
| `FieldFlags` | +0x78 | `PE_DESC_FIELD_SIZE` | unsigned int |
| `FieldValue2` | +0x88 | `PE_DESC_FIELD_VALUE2` | __int64 |
| `SectionDataPtr` | +0x118 | `PE_DESC_SECTION_DATA` | __int64 |

> 每个函数的真实用法必须**逐个对照原始反汇编**确认（不同函数用的偏移组合不同），
> 不得照抄。
