## 为什么不删除

这些文档里有大量**不可再生的一手数据**：

- 原版驱动/前端的 IDA 反编译片段与地址
- KD 双机调试的寄存器/内存快照
- 双驱动 A/B 实测的逐命令 hex 输入输出
- 蓝屏 dump 的故障定位过程
- 实机截图（`evidence/`，39MB）

删掉它们，将来若需要复核某个结论就没有依据了。所以归档而非删除。

## 已失效的结论（查阅时特别注意）

这些是归档文档里**曾经正确、后来被推翻**的判断，列出来避免误用：

1. **命名推断不可信** —— 归档文档里大量按函数名推断语义的地方，
   后续实测证明原版函数名与实物不符（见 `docs/reversing/驱动命令清单与接入指南.md` §6.1
   的"命名与实现不符"表，10 条）。
2. **"VM 里的原版驱动" 曾是我方旧构建** —— 2026-10-25 的
   `重大纠错_VM里的原版驱动实为我方旧构建_2026-10-25.md` 记录了这个事故，
   在此之前的所有 A/B 比对结论都需要重看。
3. **GT 槽位语义多次修正** —— 见 `勘误_命令槽位三次修正_2026-10-29.md`。
4. **0x026 的语义** —— 早期当作"句柄枚举"，实测是前端用来做全量进程枚举。
5. **"占位函数缺失" 的统计反复撤回** —— 审计报告里有多处此类记录，
   最终结论是"不存在连壳都没有的函数"。

## evidence/ 目录

`evidence/` 内含 99 个文件（39MB），是各文档引用的实机证据：

- `*.txt` —— CLI 输出、KD 调试记录、命令扫描结果
- `*.png` —— GUI 截图、IDA 界面、蓝屏画面
- 文件名大多带日期，与同期的文档对应

这些截图和日志无法重新生成（guest 环境、驱动版本、系统状态都已变化），
是归档里最有保留价值的部分。

## 使用建议

- **想了解协议怎么用** → 读 `docs/reversing/驱动命令清单与接入指南.md`
- **想知道某条命令的真实行为** → 同上，§4 命令清单
- **想复核某个历史结论的依据** → 在本目录按关键词搜索，证据多半在 `evidence/`
- **不要**把本目录的结论当作现状直接引用；先与代码核对的
