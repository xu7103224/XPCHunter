**`0x117 CmdEnumHookInfo` 现在返回真实 Hook 表**：`result=1`，`GT[0x8B7]=454` 条。

## 二、根因不是"缺 6 个函数"——它们本来就都在

上一轮的结论（`ParseSyscallTableExportDir` 空壳、缺 6 个被调用方）**部分不准确**。逐项核查后发现：

| 函数 | 实际状态 |
| --- | --- |
| `ReadWdfLibraryModule` | 已实现（`DriverSection.c:397`），与原始一致 |
| `FindSyscallTableDescriptor` | 已实现（`SyscallTable.c:2627`），639 字节全转写 |
| `BuildExportSectionMapping` | 已实现（`SyscallTable.c:2744`） |
| `CollectSyscallEntries4` | 已实现（`SyscallTable.c:2802`） |
| `CollectTwoSyscallTables` | 已实现（`SyscallTable.c:2841`） |
| `CollectSyscallExportEntries` | 已实现（`SyscallTable.c:2901`） |
| `ParseSyscallTableExportDir` | 已实现（`SsdtHook.c:1444`），调用序列与原始逐条一致 |

我之前创建 `SyscallChain.c` 想补这 6 个函数，发现全是重复定义，已删除。

**真正的三个原因**是环境与参数层面的：

### 2.1 旧驱动实例占着设备名（`sc start` → 183）

多次部署后 guest 里残留了旧实例。`stopall.bat` 的服务名清单里没有 `VPCHAIN`（以及一批历史名），所以旧实例一直活着，新驱动 `sc start` 返回 **183**（文件已存在），而 probe 连上的是**旧驱动**，读到的一切都是 0。

**修法**：`build/sign/stopall2.bat` 覆盖全部历史服务名（RTZ70/71/72/73/91/95/96/97/RTZS/RTZS2/RTZ56/VPCHAIN/View++ByLinxer/OrigDrv/OGT/XPCHAIN）。

### 2.2 probe 的 shape 表把 0x117 的输出压成 1 字节

`TryCommand` 对不在 `g_FeShapes` 表里的命令强制 `outSize = 1`（这是早期为了防"处理器不校验 OutSize 时爆栈"加的保护）。0x117 不在表里，于是：
- `OutputSize > 0x38` 不成立 → `EnumHookInfoOperation` **第一行就返回**，链条从未启动。

**修法**：用 `--raw 0x117 <size>`（`XpchInvoke` 直通，绕过 shape 表）。

### 2.3 输出缓冲不够大（最后一层）

`EnumHookInfoOperation` 要求：

```c
BufferSize >= 40 * (Count1 - 1) + 56
```

`Count1 = 454` 时需要 `40*453+56 = 18176` 字节。给 0x2000（8192）不够，
函数会把条目拷贝判定为失败并返回 0。

**修法**：给 `0x8000`（32768）或更大。**这是最终解锁的那一步。**

## 五、对清单的影响

Ring0 Hooks 的 3 项此前标"受阻"，实际**数据源已可用**（0x117 返回 454 条）。
剩下的是前端解析这 454 条的结构（每条 40 字节）并展示 —— 不是驱动问题。

同样解锁的还有：
- `0x42 CmdQuerySsdtInfo`（SSDT 子页）
- `0xE6/0xE7`（SSDT 表信息与恢复）
- Kernel 页的 SSDT / Shadow SSDT 子页

## 六、可复现流程

```
build\build.bat Release x64
build\sign\host_sign.bat
# guest 内：
stopall2.bat                     # 清掉所有历史驱动实例
sc create VPCHAIN type= kernel binPath= C:\Users\Public\VPChain5.sys
sc start VPCHAIN                 # 必须返回 0；返回 183 说明还有旧实例
xpch_probe.exe --live --raw 0x117 0x8000    # 必须 result=1
```

判据：`--raw` 输出 `+0x04` 应是 `0xC6 0x01`（454），`+0x2C` 起应是函数序言字节。
