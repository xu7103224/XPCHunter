## 2. 通信协议（接入必读）

### 2.1 设备与句柄

```
设备名（用户态）：  \\.\View++ByLinxer
符号链接（内核）：  \DosDevices\View++ByLinxer
```

用 `CreateFileW` 打开即可，无需额外权限协商。设备名同时是密钥派生算法的输入。

### 2.2 请求结构（0x30 = 48 字节，`pack(1)`）

| 偏移 | 大小 | 字段 | 说明 |
|---|---:|---|---|
| `0x00` | 4 | `Magic` | 固定 `0x20240810`（**加密后**写入，驱动解密后校验） |
| `0x04` | 4 | `Command` | 命令号，范围 `[0x20, 0x13A]` |
| `0x08` | 8 | `ResultBytePtr` | 驱动写回 **1 字节**结果码的地址 |
| `0x10` | 8 | `InPtr` | 命令**输入**缓冲（用户态地址） |
| `0x18` | 8 | `OutPtr` | 命令**输出**缓冲（用户态地址） |
| `0x20` | 4 | `InSize` | 输入长度 |
| `0x24` | 4 | `OutSize` | 输出长度 |
| `0x28` | 4 | `Checksum` | `MD5(明文前 0x28 字节)` 的前 4 字节 |
| `0x2C` | 4 | `Reserved` | 未使用，填 0 |

> **字段语义**：驱动处理器统一签名是
> `char Handler(PVOID In, ULONG InSize, PVOID Out, ULONG OutSize)`，
> 而分派器的寄存器映射为
> `rcx=[buf+0x10]`、`edx=[buf+0x20]`、`r8=[buf+0x18]`、`r9d=[buf+0x24]`。
> 也就是说 `+0x10` 是输入缓冲、`+0x18` 是输出缓冲、`+0x20`/`+0x24` 分别是
> **输入/输出长度**。早期文档按 "Context/Extra" 命名，是错的。

### 2.3 加密

整个 0x30 字节请求在发送前做一次自反异或：

```c
/* 加密 == 解密，同一个函数 */
for (i = 0; i < 0x30; i++)
    buf[i] = (UCHAR)~(buf[i] ^ KeyByte);     /* KeyByte = 0xCF */
```

`KeyByte` 由设备名经 `GenerateEncryptionKey` 派生。实测
`"View++ByLinxer"` → `IoControlCode = 0x05E00158`、`KeyByte = 0xCF`。
`DeviceIoControl` 使用的 `dwIoControlCode` 必须是派生出的 `0x05E00158`，不是任意值。

### 2.4 调用时序

```
1. 填明文请求（含 MD5 校验）
2. 整块加密（0x30 字节）
3. DeviceIoControl(hDev, 0x05E00158, buf, 0x30, NULL, 0, &ret, NULL)
4. 读取 *ResultBytePtr：1 = 处理器执行且成功，0 = 请求被拒或处理器返回 0
5. 从 OutPtr 读输出数据
```

### 2.5 成败判定（关键坑）

驱动的 `IoStatus.Status` **恒为 `STATUS_SUCCESS`**，`Information` 恒为 0。
所以 `DeviceIoControl` 的返回值永远为真，**成败只能看结果字节**：

| 结果字节 | 含义 |
|---:|---|
| `1` | 处理器真正执行且返回成功 |
| `0` | 请求被拒，或处理器本身返回 0 |

注意：**很多命令成功时也返回 0**（如 `0x026`）。判定应结合"结果字节 + 输出结构是否合理"，
不能只看结果字节。

### 2.6 分派器的 10 个拒绝点

| # | 条件 | 说明 |
|---:|---|---|
| 1 | `InputBufferLength != 0x30` 或系统缓冲为空 | 唯一返回 `STATUS_UNSUCCESSFUL` 的分支 |
| 2 | `IoControlCode != GT[0x1E0]` | ioctl 不匹配 |
| 3 | 解密后 `Magic != 0x20240810` | 密钥或魔法字错 |
| 4 | `MD5(前 0x28) [0..3] != [buf+0x28]` | 校验和不匹配 |
| 5 | 三指针任一 `>= MmUserProbeAddress` | 用户态地址非法 |
| 6 | `Command - 0x20 > 0x11A` | 命令号越界 |
| 7 | 驱动未就绪且 `Command != 0x22` | 只放行 `0x22` |
| 8 | `CheckProcessAccess() != 1` | 进程访问校验失败 |
| 9 | `GT[0x921 + Index] == NULL` | 该命令是空槽 |
| 10 | 重入锁 `GT[0x355] != 0` | 并发冲突 |

请求全程串行化（`KeWaitForSingleObject`，无限等待），不支持并发。

## 3. 接入示例

### 3.1 最小可用客户端（C）

```c
#include <windows.h>
#include <wincrypt.h>

#define XPCH_IOCTL   0x05E00158u
#define XPCH_KEY     0xCF
#define XPCH_MAGIC   0x20240810u
#define XPCH_REQ     0x30u

#pragma pack(push,1)
typedef struct {
    ULONG   Magic, Command;
    ULONG64 ResultBytePtr;
    ULONG64 InPtr, OutPtr;
    ULONG   InSize, OutSize, Checksum, Reserved;
} XPCH_REQUEST;
#pragma pack(pop)

static void Crypt(PUCHAR b, ULONG n) {
    ULONG i;
    for (i = 0; i < n; i++) b[i] = (UCHAR)~(b[i] ^ XPCH_KEY);
}

/* 返回 1 = 请求被驱动接受（不代表命令成功）；*Result 收到驱动写回的结果字节 */
int XpchCall(HANDLE hDev, ULONG cmd,
             void *in, ULONG inSize,
             void *out, ULONG outSize,
             UCHAR *result)
{
    XPCH_REQUEST req;
    UCHAR rc = 0;
    DWORD ret = 0;
    HCRYPTPROV prov = 0;
    HCRYPTHASH hash = 0;
    BYTE digest[16];
    DWORD dlen = sizeof(digest);

    ZeroMemory(&req, sizeof(req));
    req.Magic = XPCH_MAGIC;
    req.Command = cmd;
    req.ResultBytePtr = (ULONG64)(ULONG_PTR)&rc;
    req.InPtr  = (ULONG64)(ULONG_PTR)in;
    req.OutPtr = (ULONG64)(ULONG_PTR)out;
    req.InSize = inSize;
    req.OutSize = outSize;

    /* Checksum = MD5(前 0x28 字节) 的前 4 字节 */
    if (!CryptAcquireContextW(&prov, NULL, NULL, PROV_RSA_FULL, CRYPT_VERIFYCONTEXT))
        return 0;
    CryptCreateHash(prov, CALG_MD5, 0, 0, &hash);
    CryptHashData(hash, (BYTE *)&req, 0x28, 0);
    CryptGetHashParam(hash, HP_HASHVAL, digest, &dlen, 0);
    req.Checksum = *(ULONG *)digest;
    CryptDestroyHash(hash);
    CryptReleaseContext(prov, 0);

    Crypt((PUCHAR)&req, XPCH_REQ);
    if (!DeviceIoControl(hDev, XPCH_IOCTL, &req, XPCH_REQ,
                         NULL, 0, &ret, NULL))
        return 0;                    /* 只有 #1 拒绝点会走到这里 */

    if (result) *result = rc;
    return 1;
}
```

### 3.4 C# 接入要点

```csharp
[DllImport("kernel32.dll", SetLastError = true, CharSet = CharSet.Unicode)]
static extern IntPtr CreateFileW(string name, uint access, uint share,
                                 IntPtr sa, uint disp, uint flags, IntPtr tmpl);

[DllImport("kernel32.dll", SetLastError = true)]
static extern bool DeviceIoControl(IntPtr h, uint ioctl,
                                   byte[] inBuf, uint inSize,
                                   IntPtr outPtr, uint outSize,
                                   out uint ret, IntPtr overlapped);
```

要点：

- 请求结构用 `[StructLayout(LayoutKind.Sequential, Pack = 1)]`
- **必须先 `fixed` 住输入/输出缓冲拿到稳定地址**，再把地址写进 `InPtr`/`OutPtr`
  —— 驱动直接按用户态指针读写，不走 `METHOD_BUFFERED` 的间接拷贝
- GC 移动托管数组会让驱动读到错误数据，所以 `fixed` 作用域必须覆盖整个
  `DeviceIoControl` 调用

### 3.5 Python 接入要点

```python
import ctypes, hashlib, struct

class Req(ctypes.Structure):
    _pack_ = 1
    _fields_ = [("Magic", ctypes.c_uint32), ("Command", ctypes.c_uint32),
                ("ResultPtr", ctypes.c_uint64),
                ("InPtr", ctypes.c_uint64), ("OutPtr", ctypes.c_uint64),
                ("InSize", ctypes.c_uint32), ("OutSize", ctypes.c_uint32),
                ("Checksum", ctypes.c_uint32), ("Reserved", ctypes.c_uint32)]

KEY = 0xCF

def crypt(b):
    return bytes((~(x ^ KEY)) & 0xFF for x in b)

def call(hdev, cmd, inbuf=b"", outsize=0):
    inarr  = ctypes.create_string_buffer(inbuf, max(len(inbuf), 1))
    outarr = ctypes.create_string_buffer(max(outsize, 1))
    rc     = ctypes.c_ubyte(0)

    r = Req(0x20240810, cmd, ctypes.addressof(rc),
            ctypes.addressof(inarr)  if inbuf   else 0,
            ctypes.addressof(outarr) if outsize else 0,
            len(inbuf), outsize, 0, 0)

    r.Checksum = struct.unpack("<I",
        hashlib.md5(bytes(r)[:0x28]).digest()[:4])[0]

    raw = crypt(bytes(r))
    ret = ctypes.c_uint32(0)
    ok = ctypes.windll.kernel32.DeviceIoControl(
        hdev, 0x05E00158, raw, 0x30, None, 0,
        ctypes.byref(ret), None)
    return bool(ok), rc.value, outarr.raw
```

## 6. 接入注意事项

### 6.1 命名与实现不符的命令（历史遗留，务必核对）

原版驱动的函数名是从符号或推断得来，与真实语义并不总是一致。以下几条
已由实机验证确认，接入时按"实际行为"列理解：

| 命令 | 函数名暗示 | 实际行为 |
|---|---|---|
| `0x02A` | `CmdEnumThreads` | **进程映像路径查询**：入 8 字节 PID，出 520 字节 `WCHAR[260]` |
| `0x026` | `CmdEnumHandles` | 前端用它做**全量进程枚举**（552 字节/条，PID@+0x18） |
| `0x042` | `CmdQuerySsdtInfo` | 通用选择子枚举，`selector=0` 时输出驱动对象列表 |
| `0x0E4` | `CmdEnumProcessListWin10` | 真正的进程列表命令（`0x298` 字节/条） |
| `0x0E6` | `CmdGetSsdtTableInfo` | **TDI 两处导出指针查询**（6 个 QWORD） |
| `0x0E7` | `CmdRestoreSsdtTable` | 把 TDI 指针写回内核 |
| `0x0E8` | `CmdEnumObjectTypeInfo` | TDI PnP 客户端记录（步长 0x238） |
| `0x0EA` | `CmdQuerySsdtDetails` | NdisTcpOffloadHandlers 7 项 |
| `0x0EC` | `CmdReadExportDirectory` | NdisOidTable 双表（2MB） |
| `0x117` | `CmdEnumHookInfo` | 两张系统调用表全部条目 + 改写标志（本机 908 条） |

### 6.2 输出缓冲会被清零

多数枚举类处理器在写入前先 `RtlZeroMemory` 整个输出缓冲。所以：

- `OutSize` 要按"最大条目数 × 条目大小"给足，给小了只会拿到部分数据
- 不要假设未使用区域保留你原来的内容

### 6.3 大缓冲命令

以下命令需要 MB 级输出缓冲，给小了会返回 0 或截断：

| 命令 | 建议 OutSize | 说明 |
|---|---:|---|
| `0x026` | ≥ 2 MB | 进程条目 552 字节/条 |
| `0x031` | 2 MB | 服务表 |
| `0x033` | 2 MB | 对象枚举 |
| `0x117` | 约 18 KB（Count1=454 时） | 需 ≥ `40 × (Count1 - 1) + 56`，给小了直接返回 0 |
| `0x0E8` | 4 MB | TDI PnP 客户端，步长 0x238 |
| `0x0EC` | 2 MB | 前半当前表 + 后半原始表（+0x100000） |

### 6.4 阻塞与并发

- 驱动内部**全局串行化**：同一时刻只处理一个请求，其余无限等待
- 单条命令耗时可能较长（`0x031` 枚举服务、`0x117` 扫 908 条 hook 表）
- 用户态不要在 UI 线程同步调用耗时命令。本工程的做法是放后台线程 +
  `PostMessage` 通知主窗口，避免界面假死

### 6.5 首次调用需要初始化

除 `0x22`（`CmdQueryProcessInfo`）外，所有命令都要求驱动已完成初始化
（`GT[0x304] != 0`）。首次调用非 `0x22` 命令时，分派器会自动执行
`InitCallbackFunctions()`。若驱动刚加载，建议先调一次 `0x22` 探活。

### 6.6 版本差异

部分按 Windows 构建号分派的命令（`0x0C1` 系列进程列表、`0x0CD` GDT 等）
内部有 `if (Build < X)` 分支，输出布局随系统版本变化。接入时应先读
构建号（`0x024`）再按版本选择解析结构。

## 7. 如何复现本文的统计

```bash
cd <repo>
python - <<'EOF'
import io, re
src = 'XPCHunterDrv/src/services/IoctlDispatch.c'
s = io.open(src, encoding='utf-8', errors='replace').read()
pat = re.compile(r'Table\[(\d+)\]\s*=\s*\(PCOMMAND_HANDLER\)\s*([^;]+);')
last = {}
for m in pat.finditer(s):
    last[int(m.group(1))] = m.group(2).strip()   # 取最后一次赋值
print('slots    :', len(last))
print('implement:', sum(1 for v in last.values() if v != 'NULL'))
print('empty    :', sum(1 for v in last.values() if v == 'NULL'))
EOF
```

统计口径：以 `InitCommandHandlerTable` 中的**最后一次赋值**为准 ——
源码里保留了被注释掉的旧赋值，脚本按出现顺序覆盖，取最终态。
