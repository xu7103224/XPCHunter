# 第二步增量 1：统一刷新模型 + 列头排序（Process 页落地模式）

日期：2026-10-28
范围：**不动外观、不动驱动、不动协议**；在 `FeLoadXxx` 纯结构体模式上做数据层增量。

## 一、实现内容

### 1.1 统一刷新模型（可复用基础设施）

`frontend.c` 新增共享定时器通道，任何页面都可以接入：

```c
void (*g_AutoRefFn)(void) = NULL;   /* 当前页的定时刷新入口 */
#define FE_AUTOREF_TIMER_ID  0x0A01u
```

- `WM_TIMER` 里若 `wParam == FE_AUTOREF_TIMER_ID && g_AutoRefFn` → 调它；
- `WM_DESTROY` 里 `KillTimer`；
- 页面模块自己管开关：置 `g_AutoRefFn` + `SetTimer` 开，`KillTimer` + 置 NULL 关。

页面上落地成 `FeProcPageToggleAuto(HWND)`（`BS_AUTOCHECKBOX` 按钮
`IDC_PROC_AUTO`，2 秒周期）。按钮由 `FeProcPagePageShow` 控制只在本页可见，
并在 `WM_SIZE` 的 Process 分支里贴状态行右端随窗口重排。

### 1.2 列头点击排序（缓存 + 索引 qsort）

`DoRefreshProcs` 从"载入→逐行渲染→释放"改为"载入→进缓存→渲染"：

```c
FE_PROCESS_LIST g_ProcCache;      /* 列表缓存（排序/重绘不再重查驱动） */
unsigned char  *g_ProcAcc;        /* Ring3 可访问性，与 Items 平行 */
BOOL g_ProcCacheValid;
int  g_ProcSortCol  = -1;         /* -1 = 维持驱动枚举序 */
int  g_ProcSortDesc = 0;
```

- 映像路径 `FeLoadProcessPathWin32` 与 Ring3 可访问性都在**刷新时一次性**
  解析进缓存（原来在渲染循环里逐行查，排序时会重复 N 次）；
- `ProcRenderRows()` 在缓存索引上 `qsort(order, n, sizeof(int), ProcCmp)`
  后整体重绘，5 列文本逻辑与原实现逐字一致；
- `ProcCmp` 按列比较：PID/EPROCESS 数值、Name 定长 16 字节、Path `wcscmp`、
  Ring3 状态 0<1；**同键回落到枚举序索引**，保证排序稳定；
- 同列再点反向，异列重新升序（`FeProcPageOnColumnClick`）；
- `WM_NOTIFY` 新增 `LVN_COLUMNCLICK` 分支转进去。

## 二、验收

### 2.1 排序器（`--selftest-sort-cli`，进程内确定性验证）

跨进程读 `LVM_GETITEMTEXTA` 的指针不封送，GUI 侧无法可靠取证；因此新增一个
CLI 自检入口，在进程内直接驱动同一个 `ProcCmp`，喂 5 行合成样本（PID
300/100/500/200/400 故意乱序）：

```
sort selftest: 5 rows, columns 0..4, asc+desc
  col0 asc : pids=100,200,300,400,500
  col0 desc: pids=500,400,300,200,100
  col1 asc : pids=100,200,300,400,500
  col1 desc: pids=500,400,300,200,100
  col2 asc : pids=100,200,300,400,500
  col2 desc: pids=500,400,300,200,100
  col3 asc : pids=100,200,300,400,500
  col3 desc: pids=500,400,300,200,100
  col4 asc : pids=100,200,300,500,400
  col4 desc: pids=400,500,300,200,100
sort selftest: PASSED
```

col4（Ring3 状态）的 `100,200,300,500,400` 正是"0 组在前、组内保持枚举序"
的预期结果。另有排列完整性断言（5 个索引必须恰好覆盖 0..4）与 PID 单调性断言。

### 2.2 Auto Refresh 开关（跨进程 UI 验证）

计划任务在交互会话启动客户端后，用 UI 探针读按钮文本，`BM_CLICK` 驱动：

```
btn0: 'Auto Refresh: OFF'
btn1(ON): 'Auto Refresh: ON (2s)'
btn1(+5s): 'Auto Refresh: ON (2s)' rows 0->0   （该轮驱动未起，列表为空）
btn2(OFF): 'Auto Refresh: OFF'
```

开关状态机与按钮文案均正确。列表行数在驱动就绪的轮次为 10 行。

### 2.3 CLI 防回归（同 boot 背靠背双客户端）

参照客户端 = HEAD~1（`676e80a`，拆分前单文件）独立 worktree 构建，
与当前构建在**同一次开机**内背靠背跑全量 sweep：

| 分类 | 条数 | 说明 |
|---|---|---|
| 逐字节一致 | **37** | 全部驱动命令（kernel/idt/ssdt/ring0/hiddendrv/proclist/network/scan/...） |

## 三、踩坑记录（供后续复用）

1. **跨进程 `LVM_GETITEMTEXTA` 无效**：`pszText` 是远端指针，`SendMessage`
   不做指针封送，返回空串；`GetWindowTextA` 对编辑/静态控件可用，但对
   自绘/列表项无效。GUI 行为验证要么进程内（加 CLI 自检），要么 UIA。
2. **UIA 只能看到主窗口**：本项目没有启用 UIA provider，`ControlType.List`
   查不到 Win32 ListView → 退回 Win32 探针 + 进程内自检的组合。
3. **截图与桌面不同步**：`con_screenshot`（guest tools）拍到的画面可能没有
   目标窗口，即使 `EnumWindows` 明确报告 `vis=True` 且给出正确矩形。以
   探针数据（句柄/矩形/文本/可见性）为准，截图只作辅助。
4. **计划任务与探针必须同会话**：`schtasks /ru xuq /rl HIGHEST` 起的进程在
   Console 会话；SSH 会话（session 0）枚举不到它的窗口。探针也要用计划任务
   在 Console 会话里跑。
5. **驱动不会跨重启自动加载**：`sc create` 的 demand 驱动重启后是 STOPPED，
   每轮 sweep 前必须 `sc start XPCHunterDrv`，否则所有驱动命令退化为
   `open device failed`。
6. **`printf` 的 `\t` 陷阱**：git-bash 的 `printf` 会把 `\t` 解释成制表符，
   生成 bat 一律用 heredoc。
