# 第二步增量 5：刷新模型统一（变更触发 + 跨页推广）

完成"手动 / 定时 / 变更触发"三种刷新模式，并把定时刷新推广到其它页。

## 一、变更触发（Process 页）

定时刷新不再无条件重绘：先算指纹，只有内容真的变了才重建列表。

```c
ULONG64 ProcComputeFingerprint(void);       /* FNV-1a over (PID, EPROCESS) */
BOOL    DoRefreshProcsIfChanged(void);      /* 定时入口 */
```

- **指纹**：对 `(PID, EPROCESS)` 序列做 FNV-1a（64 位），顺序敏感；
- **无变化时**：释放刚查回来的新列表，保持现列表不动——不闪烁、不丢选中行、
  不打断用户的排序/滚动位置；
- **有变化时**：整块替换缓存（与 `DoRefreshProcs` 的缓存管理一致，含路径解析
  与 Ring3 可访问性），重绘并在状态栏追加 `[changed]`；
- **手动刷新**（Refresh 按钮 / Kill 后重查 / 下钻）仍走 `DoRefreshProcs`
  强制路径，不受指纹限制——用户点了刷新就应该看到刷新；
- 手动刷新结束时同步指纹，否则下一次定时轮询会把"无变化"误判成变化。

## 二、跨页推广（`g_AutoRefFn`）

`ShowPage` 在切页时决定定时器绑到谁（3 秒周期）：

| 主 Tab | 定时刷新入口 |
|---|---|
| 0 Process | 由本页开关控制（`FeProcPageToggleAuto`，2s，变更触发） |
| 1 Kernel | `DoRefreshKernel` |
| 2 / 3 Ring0 / Ring3 Hooks | `DoRefreshHooks` |
| 6 Startup | `DoRefreshStartup` |
| 7 Services | `DoRefreshServices` |
| 13 Other | `DoRefreshOther` |
| 其余 | 无定时刷新（停掉定时器） |

所有权用 `g_ProcAutoOwnedTimer` 区分：Process 页自管自己的 2s 定时器，
离开该页时 `ShowPage` 先把它停掉，避免两页抢同一个 timer id。

## 三、验收

### 3.1 指纹自检（`--selftest-changed-cli`，进程内断言）

```
changed selftest: stable:   B2AF5D021BEA7828 == B2AF5D021BEA7828 OK
changed selftest: pid-chg:  B2AF5D021BEA7828 != A88D67B5B8D3463D OK
changed selftest: eproc-chg:B2AF5D021BEA7828 != E50828DB48B93B1D OK
changed selftest: order-chg:B2AF5D021BEA7828 != A9597A9A3A48DB38 OK
changed selftest: PASSED
```

四个断言：同内容稳定、PID 变化必变、EPROCESS 变化必变、顺序变化必变
（进程列表顺序即驱动枚举顺序，序变视为变化，避免漏判）。

### 3.2 既有自检未回归

```
filter selftest: PASSED          （10 用例）
export selftest: PASSED          （231B 逐字节 + 过滤参与）
```
