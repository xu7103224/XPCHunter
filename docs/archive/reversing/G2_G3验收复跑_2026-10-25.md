## 2. G2-b：0x110–0x13A 双驱动逐字节差分

同一支探针、同一台机、分别加载两个驱动，各跑一次：

```
xpch_probe.exe --live --handshake --matrix --matrix-lo 272 --matrix-hi 314 \
    --matrix-out m_hi_{mine,orig}.txt
```

差分脚本对每行比较 `InSize / OutSize / result / 输出 hex`：

```
orig entries: 42  mine: 42

=== 状态差异 0 条 ===

=== 输出 hex 差异 0 条 ===
```

**42 条命令状态与输出字节完全一致。** 两边仅 2 条 OK（0x116、0x139），
其余 40 条 REJECTED，行为相同。

证据：`build/audit/m_hi_orig.txt`（原版）· `build/audit/m_hi_mine.txt`（我方）
—— 两份文件均为 1231 字节。

### 2.1 关于"逐字节一致"的适用边界

同一份 235 条低段矩阵跨多次运行（`m_reg2` / `m_final` / `m_v`，分别在不同
时间、含一次 guest 重启）做**状态列**比对：

```
m_reg2 vs m_v 状态差异: 0
m_final vs m_v 状态差异: 0
```

但若做**全字节**比对，有 4 条会不同：0x026 / 0x0E4 / 0x0E8 / 0x10B。
逐条核对后确认，差异全部落在**运行时内核地址**上（EPROCESS 指针、
回调函数地址、以及随之产生的 FILETIME 高位），前 16 字节的结构字段
（如 0x0E4 的 `...53797374656D0000` = `System`）完全一致。

原因：这些命令输出的是**活体内核对象地址**，随每次启动的
内核模块基址（ASLR）变化。原版基线 `m_o1.txt` 采集于 10-23，
与今天的内核布局本就不同，因此这类字段**不可跨会话逐字节比较**。

**正确口径**：
- 状态列（InSize / OutSize / result / OK-REJ）—— 必须完全一致 → 实测仅 0x20 一条；
- 结构字段（类型码、名称、计数字段）—— 必须一致 → 一致；
- 内核地址 / 时间戳 —— 允许随会话变化，不作为差异判据。

0x110–0x13A 段两次采集（原版与我方）恰好在同一次会话内完成，
因此连地址都一致，是 0 差异。

✔ **通过**
