# 原版前端 × 我方驱动：兼容性验证记录（2026-10-20）

目标：用原版 `PCHunter64.exe` 驱动我方实现的 `XPCHunterDrv.sys`，
以「原版前端 + 兼容驱动」的方式还原原版功能。

---

## 一、原版前端如何定位驱动（静态证据）

在 `PCHunter64.exe` 里搜索宽字符串，得到以下三组，位置连续：

```
文件偏移 0x456F88:  "View++_Driver64.sys\0\\\\tsclient\\\0\\drivers\\View++_Driver64.sys\0"
文件偏移 0x457010:  "View++ByLinxer\0\0View++\0\0Process\0..."
```

对应 VA（IDB 中 `find_bytes` 命中）：

| 内容 | VA |
|---|---|
| `View++ByLinxer`（宽） | `0x140458610` |

据此确定原版前端使用的三个名字：

| 用途 | 值 |
|---|---|
| 驱动文件名 | `View++_Driver64.sys` |
| 驱动落盘路径 | `\drivers\View++_Driver64.sys` |
| 设备/服务名 | `View++ByLinxer` → `\\.\View++ByLinxer` |

原版前端通过 SCM 加载（exe 内可见 `OpenSCManager` / `CreateService` /
`StartService` 的 ANSI 导入名，以及 `ZwLoadDriver`）。

## 二、部署方式（已实测通过）

把我方签名驱动**直接**以原版文件名安装：

```bat
copy /y XPCHunterDrv_signed.sys C:\Windows\System32\drivers\View++_Driver64.sys
sc create View++ByLinxer type= kernel start= demand ^
    binPath= C:\Windows\System32\drivers\View++_Driver64.sys
sc start View++ByLinxer
```

结果：`STATE: 4 RUNNING`，`WIN32_EXIT_CODE: 0`。
kd 中模块名为 `View___Driver64`（`+` 被替换为 `_`），基址可见。

## 三、为验证兼容性新增的观测手段

由于原版前端是 GUI 程序、无法用 `vmrun` 直接观察其界面，
在驱动里加入两组只读统计，经诊断命令导出：

### 1. 每命令调用统计

`DispatchDeviceControl` 在处理器返回后写入：

| 槽位 | 含义 |
|---|---|
| `GT[0x4800 + i]` | 命令 `0x20+i` 的调用次数 |
| `GT[0x4A00 + i]` | 最近一次结果码 |
| `GT[0x4C00 + i]` | 最近一次调用进程 PID |

### 2. 设备打开统计

`DispatchCreateClose` 在 `IRP_MJ_CREATE` 时写入：

| 槽位 | 含义 |
|---|---|
| `GT[0x4E00]` | 设备累计打开次数 |
| `GT[0x4E01]` | 最近一次打开者 PID |

以上槽位（`0x4800..0x4FFF`）是全局表末尾 2048 个空闲项，原始驱动从未引用，
不影响 GT 对比审计。

### 3. 导出命令

命令 `0x13A` 在原始命令表中是**空槽**（`Table[282]`），任何前端都不会发送。
本实现挂了一个只读处理器 `CmdDumpCallStats`，把上述统计按 16 字节/项导出：

```
+0x00 ULONG Command      (0xFFFE 表示"设备打开次数"记录)
+0x04 ULONG CallCount
+0x08 ULONG LastResult
+0x0C ULONG LastCallerPid
```

用户态：`xpch_probe.exe --live --stats`

## 四、实测结果

### 阶段一：Session 0（vmrun runProgramInGuest）

| 项目 | 结果 |
|---|---|
| 我方驱动以原版文件名加载 | 成功，`STATE: 4 RUNNING` |
| 原版 `PCHunter64.exe` 进程启动 | 成功，进程常驻 |
| 原版前端打开 `\\.\View++ByLinxer` | **未发生** |
| 原版前端发送任何命令 | **未发生** |

`tasklist /v` 显示该实例落在 `会话名: Services`、`会话#: 0`，
窗口标题为空——MFC UI 在 Session 0 无法初始化。

### 阶段二：Session 1（交互桌面，计划任务 /IT 启动）

为排除会话因素，配置 guest 自动登录（`AutoAdminLogon=1`、
`DefaultUserName=xuq`、`AutoLogonCount=30`、`ForceAutoLogon=1`），
重启后确认 `Explorer.EXE` 以 `xuq` 身份运行。

再用计划任务以交互方式启动：

```bat
schtasks /create /tn XPCH_FE /tr "C:\Users\Public\PCHunter64.exe" ^
    /sc once /st 23:45 /ru xuq /rp 123 /it /rl HIGHEST /f
schtasks /run /tn XPCH_FE
```

`tasklist /v` 结果：

```
映像名称:  PCHunter64.exe
PID:       5788
会话名  :  Console
会话#   :  1
窗口标题:  暂缺
```

**这次确实进入了交互桌面**，但驱动侧统计仍然只有 probe 自己：

```
stats dump 0x13A -> OK, result=1
  0x22   count=2  lastResult=1  lastPid=4504
  0x13A  count=1  lastResult=1  lastPid=2132
  0xFFFE count=2  lastResult=0  lastPid=4504     <- 只有 probe 自己
3 command(s) invoked since load
```

### 阶段三：截图定位真正的阻塞点

`con_screenshot method=guest` 抓到的桌面显示，原版前端弹出一个对话框：

```
标题: yjxtmamtng
正文: License过期！
按钮: 确定
```

窗口标题 `yjxtmamtng` 与 Session 0 实例的 `kutvxpl` 一致——都是
运行时随机生成的（反调试/反分析手段），说明程序已正常跑到自己的
校验阶段。

## 五、结论

**原版前端在加载驱动之前先做许可证校验，校验失败就停在
「License过期！」对话框，根本不会去 open 设备。**

这是决定性的证据，说明：

1. 我方驱动与「原版前端不使用驱动」这一现象**无关**；
2. 该样本（`PCHunter_2024.09.02`）的许可证已于当前日期（2026-10-20）
   过期，程序在启动早期即中止；
3. 因此在本环境下**无法**通过原版前端完成 GUI 级兼容性验证——
   这与驱动实现无关，是样本自身的授权限制。

### 已经可以确认的兼容性事实

| 层次 | 状态 | 证据 |
|---|---|---|
| 驱动加载 | 通过 | `STATE: 4 RUNNING`，`WIN32_EXIT_CODE: 0` |
| 设备名 / 服务名约定 | 通过 | 原版前端的三个字符串全部匹配 |
| 设备可打开 | 通过 | probe 以 `\\.\View++ByLinxer` 成功 open |
| 密钥派生 | 通过 | 用户态复算 `ioctl=0x05E00158`、`key=0xCF` == 驱动 GT |
| 请求加密 / MD5 校验 | 通过 | 请求被驱动接受并分派到处理器 |
| 命令分派 | 通过 | 283 条命令全扫描，处理器可达，零崩溃 |
| 首条命令（0x22 就绪标志） | 通过 | `result=1`，`GT[0x304]` 置位 |
| 第二条命令（0x24 读构建号） | 通过 | `result=1`，返回 `18362` |

协议层与分派层已全部对齐；剩余差异只在各命令的业务参数上
（257 条 REJECTED 需要前端选择真实的进程/对象/注册表键）。

## 六、后续可行的验证路径

若要在 GUI 级完成验证，需要以下任一条件：

1. 一份**未过期的** PCHunter 前端（本样本的 license 已过期）；
2. 或按原版前端的命令序列，用我们自己的前端补齐业务参数
   （`XPCHunterUM/src/frontend.c` 已具备骨架与形状表）。

---

## 七、可复现的验证脚本

- `build/audit/compat_orig_frontend.bat`：以原版文件名安装我方驱动、
  建服务、启动、拉起原版前端并检查进程存活。
- `build/audit/set_autologon.bat`：配置 guest 自动登录（Session 1 前提）。
- `build/audit/launch_session1.bat`：用 `schtasks /IT` 在交互桌面
  启动原版前端（`vmrun runProgramInGuest` 只能进 Session 0）。
- `xpch_probe.exe --live --stats`：读取驱动侧统计，
  用 `lastPid` 区分「原版前端」与「探针自己」。

判定规则：若 `--stats` 输出中出现**非 probe 的 PID** 且其命令计数非零，
即可证明原版前端确实在驱动中执行了命令。当前实测未出现该 PID，
原因已由截图证实（License 过期，未进入驱动使用阶段）。
