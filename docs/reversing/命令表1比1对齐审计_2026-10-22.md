# 命令表 1:1 对齐审计（2026-10-22）

## 方法

原版的命令表由 `InitCommandHandlerTable`（IDA `0x1400815B0`，`0xE1B` 字节）
一次性填满，共 282 个槽（索引 0..281，对应命令 `0x20..0x13A`）。
本次逐槽提取原版的 282 条赋值，与 `XPCHunterDrv/src/services/IoctlDispatch.c`
的 `Table[]` 全集做机器比对（脚本见本文末尾）。

原始数据落盘在 `build/audit/orig_table.txt`。

## 结论一：空槽数量完全一致

| 项 | 数量 |
| --- | --- |
| 原版空槽（`v0[i]=0` 或 `memset`） | **34** |
| 我方空槽 | **34** |
| **原版有实现、我方为空** | **0** |
| **原版为空、我方有实现** | **0** |

此前清单里记的"85 个空槽"是把**协议级拒绝**（OutSize 不符、入参不符等）
也当成了"未实现"。实际按命令表看，**没有任何一条原版命令在我方缺失**。

34 个空槽是原版驱动的设计：
- `v0[3]`、`v0[97]`、`v0[98]`、`v0[121]`、`v0[122]`、`v0[123]`、
  `v0[165]`、`v0[166]` —— 逐条赋值 0
- `memset(v0+105, 0, 0x30)` —— 索引 105..110
- `memset(v0+114, 0, 0x30)` —— 索引 114..119
- `memset(v0+131, 0, 0x40)` —— 索引 131..138
- `memset(v0+185, 0, 0x30)` —— 索引 185..190

## 结论二：29 处命名差异，无一处是挂错实现

比对出的 29 条"不同名"全部属于两类：

**A. 我方多加了 `Cmd` 前缀（原版注册名没有）**

    0x72  orig=PowerCallbackUnregister       ours=CmdPowerCallbackUnregister

**B. IDA 命名与实物不符（我们在注释里已留档）**

    0x29  orig=CmdHandleStreamProcessInput   ours=CmdMiniFilterStreamHandle
    0xC7  orig=CmdSetCallbackFlagTrue        ours=MiniFilterClientContext
    0xC8  orig=CmdSetCallbackFlagFalse       ours=MiniFilterServerContext
    0xDF  orig=CmdOpenFilterVolumeFile       ours=MiniFilterInstanceSetup
    0xE0  orig=CmdRemoveFilterContextNode    ours=MiniFilterInstanceQuery
    0xF1  orig=CmdInitFwpsDispatchTables2    ours=MiniFilterAcquireForModWrite
    0x112 orig=CmdEnumAleEndpointLayers      ours=MiniFilterPreFastIo

B 类逐条核对过函数体，两边是同一实现：
- `0xF1` 原版 `CmdInitFwpsDispatchTables2` 的伪代码实为"读 Fwps 调度表并拷到
  输出缓冲"（`GtRead(0x7FC)` → `InitFwpsDispatchTables` → `memmove`），
  与我方 `MiniFilterAcquireForModWrite` 逐行一致。
- `0x112` 原版 `CmdEnumAleEndpointLayers` → `EnumerateAleEndpointLayers`，
  而后者实际枚举的是 `\FileSystem\RAW` 层（注释已留档），
  与我方 `MiniFilterPreFastIo` 一致。

## 结论三：Network 页的真实瓶颈已确认

`0x112` 看起来像 Network 的数据源（名字是 ALE 端点层），但
`EnumerateAleEndpointLayers` 的 8 个层标识 DWORD 解码后是
`\FileSystem\RAW`，属于文件系统过滤层，与 NDIS/WFP 的 ALE 无关。
**Network 页的 30 项在原驱动里没有对应命令**，这一判断现在有命令表
逐槽审计support，不再只是"没找到"。

## 比对脚本

```python
import io, re
orig = {}
for line in io.open('build/audit/orig_table.txt', encoding='utf-8'):
    line = line.strip()
    if not line:
        continue
    i, n = line.split(' ', 1)
    orig[int(i)] = n.strip()

src = io.open('XPCHunterDrv/src/services/IoctlDispatch.c', encoding='utf-8').read()
ours = {}
for m in re.finditer(r'Table\[(\d+)\]\s*=\s*\(PCOMMAND_HANDLER\)([A-Za-z_0-9]+)', src):
    ours[int(m.group(1))] = m.group(2)
for m in re.finditer(r'RtlZeroMemory\(&Table\[(\d+)\],\s*(0x[0-9A-Fa-f]+)\)', src):
    st, sz = int(m.group(1)), int(m.group(2), 16)
    for k in range(st, st + sz // 8):
        ours[k] = 'NULL'

null = lambda v: v in (None, 'NULL', '0')
missing = [i for i in range(282) if not null(orig.get(i)) and null(ours.get(i))]
extra   = [i for i in range(282) if null(orig.get(i)) and not null(ours.get(i))]
```

输出：`missing=0`、`extra=0`。
