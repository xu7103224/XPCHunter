# 【重大纠错】VM 中的"原版驱动"实为我方驱动的旧构建

## 结论

VM（Win10_Dev）里 `View++ByLinxer` 服务加载的
`C:\Windows\System32\drivers\ViewPlusPlusByLinxer.sys`
**不是 PCHunter 原厂驱动**，而是本项目自己某轮构建的产物。

因此，**此前所有以该文件为"原版"做的对照实验与结论，全部无效**。

---

## 证据

### 1. 三个不同的二进制

| 文件 | 大小 | PE 时间戳 | MD5 |
|---|---|---|---|
| `samples/PCHunter_2024.09.02/View++_Driver64.sys`（样本，IDA 一直分析的这个） | 689,664 | 2024-09-01 16:55 | `f778e54132fe131481d59c0d1075f37d` |
| `samples/guest_ViewPlusPlusByLinxer.sys`（**从 VM 里拉回来的**） | 706,960 | **2026-10-22 20:18** | `d7c3e294adbc7cbe9ba76d400a776bb6` |
| `build/sign/OrigDrv.sys`（另一个备份） | 691,088 | 2024-09-01 16:55 | `6d238ab5d0d5fe41a8c68bee1d0f7951` |

VM 里那份的时间戳是 **2026-10-22**，落在本项目开发期间，
而作者发布版是 2024-09-01。

### 2. 与作者发布版的实质差异

| 特征 | 样本（发布版） | VM 里那份 |
|---|---|---|
| `.rsrc` 节 | **有**（含 `(C) 2008-2025 linxer@163.com`、`FileVersion 1.0.6.0`） | **无** |
| 节布局 | `.text 0x8bb7a` / `.rdata 0x6f94` / `.data 0x39420` | `.text 0x87a69` / `.rdata 0x1c4ac` / `.data 0x2d700` |
| 字符串 | 98 | 117 |

`.rsrc` 里有作者的版权与版本信息，**VM 里那份完全没有** ——
一个正规发布的内核驱动不会没有版本资源。

### 3. 与**我方驱动**的高度一致

| 项 | VM 里那份 | `XPCHunterDrv.sys` |
|---|---|---|
| 导入 DLL 集合 | `ntoskrnl.exe` / `HAL.dll` / `FLTMGR.SYS` | **完全相同** |
| 导入函数总数 | 94 | **94** |
| 导入函数集合 | 94 个 | **完全包含，无一多无一少** |
| `.data` 大小 | `0x2d700` | **`0x2d700`（一致）** |
| `INIT` 大小 | `0xb84` | **`0xb84`（一致）** |
| `.reloc` 大小 | `0xd8` | **`0xd8`（一致）** |
| `.text` 大小 | `0x87a69` | `0x88669`（略大，即更晚的构建） |

**94 个导入函数完全一致、三个节大小完全一致**，这不可能是巧合。
VM 里那份就是我方驱动的一个稍早构建。

## 影响范围

### 直接作废的结论

1. **A/B 逐条比对报告**（`双驱动AB逐条比对报告_2026-10-25.md`）
   报告中的「原版」列实际是"我方旧构建"。所谓 8 条状态差异
   （0x021 / 0x026 / 0x027 / 0x0D4 / 0x0E1 / 0x0E8 / 0x0FC / 0x10B）
   是**我方新旧两个构建之间**的差异，不是"我方 vs 原版"的差异。

2. **0xE1 的"原版有数据"**：那是旧构建有数据，新构建没有 ——
   说明这是**我方在两次构建之间引入的回归**，而非与原版的差距。

3. **0x78 / 0xC2 / 0xEC「原版也崩」**：那是旧构建也崩，
   同样是我方代码的问题，不能用来证明"原版也这样"。

4. 所有「原版同样 REJ」「原版 xref=0」类的对照结论，只要用到了
   运行时加载的那份驱动，都需要重新验证。

### 不受影响的结论

- 纯静态分析结论（IDA 对 `samples/PCHunter_2024.09.02/View++_Driver64.sys`
  的反汇编、xref 统计、字符串搜索）—— 那是真正的作者发布版，
  但**需要确认它与 VM 环境无关**，只能作为算法参考。
- 我方自身代码的静态审查、编译修复、验收门 G2/G3/G4/G5
  （这些只依赖我方驱动）。
- 命令表 1:1 对齐审计（基于样本反汇编）。

## 根因推测

`build/sign/` 下有 `OrigDrv.sys` 等备份，历史上多轮"测试原版驱动"
很可能在某次操作中把我方构建误部署到了 `ViewPlusPlusByLinxer`
服务名下（两者服务名不同但设备名相同，此前的记录里提过
"原始驱动与我方驱动不能同时加载（设备名冲突）"，
说明两者的设备名一致 —— 这也解释了为什么能互换）。
