# Kernel 页落地（2026-10-21）

## 一、本轮范围

原版前端 14 个主 Tab 的第 2 个是 **Kernel（内核）**，它有 11 个子页：

```
Kernel Module / Driver / Hidden Drivers / Suspicious DriverObject /
IDT / GDT / SSDT / Shadow SSDT / I/O Port / Device / Object
```

本轮先落 **Kernel Module** 与 **Driver** 两个子页，并取得实机截图证据；
其余 9 个子页留待后续（各自需要不同的数据源与逆向工作，见第五节）。

## 二、驱动侧：先修掉 0x25 / 0x3C 的两处移植错误

原计划以驱动命令 `0x25 CmdEnumKernelDrivers` 与 `0x3C CmdEnumKernelModules`
作为数据源。实机一跑就出问题：`--raw 0x25` 直接把 guest 打到自旋
（vmware-vmx 进程 CPU 147%），最终 bugcheck 0x139。回到 IDA 逐条比对，
发现两处移植错误。

### 2.1 `CmdEnumKernelDrivers`(0x14004F340)：入参上下文是 24 字节，不是 1 字节

原始在栈上构造 24 字节上下文（反编译变量 `v18[8] / v19 / v20`）：

```c
v20 = pDriverObjectFunc();      /* +16 = IoGetCurrentProcess()      */
v19 = pObjectTypeFunc();        /* +8  = PsGetCurrentProcessId()    */
v18[0] = 1;                     /* +0  = InfoFlag                   */
v12 = pCurrentThreadFunc();     /* PsGetCurrentThreadId()，用于过滤自身条目 */
v7  = EnumProcessInformationWorker(v18, OutputBuffer, BufferSize);
```

`EnumProcessInformationWorker` 把 `+8` 当 PID 传给
`PsLookupProcessByProcessId`、把 `+16` 当 EPROCESS 传给
`ValidateProcessObject`/`ReferenceObjectSafe`。

旧移植只声明了 `char HasData = 1;` 并把它当上下文传入 —— **`+8` / `+16`
是未初始化的栈垃圾**，内核拿垃圾值去查进程对象。这就是打崩的原因。

三个函数指针槽的真实含义（用 ntoskrnl 导出表反查基线槽位确认）：

| 枚举名 | 槽 | 组 | 真实导出 |
| --- | --- | --- | --- |
| `GtObjectTypeRefFunc` | 0x4226 | 68 | `PsGetCurrentProcessId` |
| `GtTotalSize\|GtObjectTypeField42\|GtDriverObject` | 0x4271 | 93 | `IoGetCurrentProcess` |
| `GtUninstallHookSyscallPeOffset\|GtEprocessField120` | 0x42AA | 112 | `PsGetCurrentThreadId` |

### 2.2 `CmdEnumKernelModules`(0x14004F9F4)：本地上下文 24 字节 + BufferSize 取错

```asm
0x14004FA75  movups xmm0, [rbx]        ; 拷前 16 字节
0x14004FA78  movups [rbp-0x20], xmm0
0x14004FA7D  movsd  xmm1, [rbx+0x10]   ; 再拷 8 字节
0x14004FA82  movsd  [rbp-0x10], xmm1   ; → 局部上下文共 24 字节
0x14004FA09  mov esi, r9d              ; esi = 本函数第 4 参数 OutputSize
0x14004FA88  mov r8d, esi              ; worker 的 BufferSize = OutputSize
```

旧移植：
- 用 `_OWORD Buffer`（16 字节）承接后又让 worker 读 `+16` → **栈越界读**；
- 把 worker 的 BufferSize 写成输入里的 `+16` 那个 qword，而原始用的是
  本函数的 `OutputSize` 参数。

两处已按原始重写。

> **状态说明（诚实记录）**：这两处修正后的实机验证**尚未完成**。
> guest 在这条路径上反复不稳定（多次自旋/挂起，需要硬复位），
> 因此 Kernel 页本轮改用下面第三节的纯用户态数据源落地。
> 0x25/0x3C 的验证仍待补。

## 三、用户态数据层（`XPCHunterUM/src/KernelViews.c`）

| 子页 | 数据源 | 列 |
| --- | --- | --- |
| Kernel Module | psapi `EnumDeviceDrivers` + `GetDeviceDriverBaseNameW` / `GetDeviceDriverFileNameW` | Base / Size / Name / Path |
| Driver | SCM `EnumServicesStatusExW(SERVICE_DRIVER)` + `QueryServiceConfigW` | Service / State / Start / ImagePath |

两个要点：

1. **`EnumDeviceDrivers` 只返回基址数组**，不返回大小。大小用**相邻基址差值**
   推算（先按基址排序，最后一个记为 0）。这与多数 ARK 工具的做法一致，
   但严格说最后一个模块（通常是 `monitor.sys` 之类）拿不到真实大小。
   等驱动侧 0x25 验通后，可以用内核链表里的 `DriverSection->SizeOfImage`
   校正。
2. `QueryServiceConfigW` 的字段名是 **`lpBinaryPathName`**，不是注册表里的
   `ImagePath` —— 第一次写错，编译报 `C2039`。

## 五、剩余 9 个子页的数据源规划

| 子页 | 需要的驱动能力 | 状态 |
| --- | --- | --- |
| Hidden Drivers | 驱动对象链表遍历 + 与 `\Driver` 对象目录比对 | 待逆向 |
| Suspicious DriverObject | `DRIVER_OBJECT` 段/大小与磁盘映像比对 | 待逆向 |
| IDT | `sidt` + 每项指向的模块归属 | 可用 `0xCD CmdCollectAllCpuGdtEntries` / 自实现 `sidt` |
| GDT | `sgdt` + 选择子解析 | 同上 |
| SSDT | `0x42 CmdQuerySsdtInfo` + `0xE6/0xE7` | 驱动侧已在 HANDLED 集合 |
| Shadow SSDT | `0xB0..0xC0` 系列 | 驱动侧已在 HANDLED 集合 |
| I/O Port | `0x46 CmdIoPortOperation` | 驱动侧已在 HANDLED 集合 |
| Device | 设备对象树遍历 | 待逆向 |
| Object | `0x33 CmdEnumObjects` / `0x56 CmdEnumObjectAllTypes` | 驱动侧已在 HANDLED 集合 |

## 六、本轮踩到的环境问题（已解决，记下来避免重复）

1. **guest 装的是 Win10 1903 的开发版，未安装 OpenSSH Server** ——
   所以 `term_open` / `con_run` / `con_autologon` 这些走 SSH 的工具全部失败，
   只有 `vmrun`（VMware Tools）与控制台 VNC 可用。vmrun 的
   `runProgramInGuest` 默认落在**会话 0**，GUI 程序需要经**计划任务**投递到
   交互会话（`schtasks /create ... /ru xuq /rl HIGHEST` + `schtasks /run`）。
2. **`vm_start` 在 VM 有 saved state 时会恢复那个状态**，会把之前自旋/崩溃的
   内核状态一起带回来。干净启动必须 `vm_start(discard_saved_state=true)`。
3. 控制台截图在**锁屏界面也能取到**（`con_screenshot` 默认 `method=auto`
   走 guest 路径需要能登录；`method=vnc` 在无交互会话时是黑的）。
   解锁顺序：点一下屏幕 → 出现密码框 → `{password}{enter}`。
